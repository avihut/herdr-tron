# Portable native-layout workflow

This is a portable guide for maintaining TRON. The installed host's current AGENTS.md, CLAUDE.md, LAYOUT_GUIDE.md and generated API types remain authoritative.

1. Read current host rules and type declarations. These are native GPUI mods, not web views. Do not modify shipped mods, generated declarations or another layout's source.
2. Research source-world production design with primary references; inspect real imagery. Separate canonical details from original interface adaptations. Create original geometry and illustrations; keep licenses.
3. Preserve actual Herdr names, addresses, statuses and explicit action targets. Cosmetic preferences never change agent behavior. Keep terminals primary and controls legible in dark and light. Test retained terminal colors before changing their background.
4. Implement pure game/parser/math modules with full victory paths and failure cases. Games need restart, outcome feedback, persistence and a normal access path. Secrets must not execute commands, change files or surprise the user with destructive actions.
5. Use native animation and a reduced-motion control. Prefer manual bounded projected geometry over JavaScript redraw loops. Poll only actual sampled data at a modest rate and guard overlap.
6. Give the layout a native content-sized pointer picker: real layout names, replacement filtering, title conventions and active marker. Keep long lists scrollable and reserve system window controls.
7. Validate a complete staged package outside watched mods. Place the non-docking manifest before the entry point; atomically swap complete folders; write layout last. Refuse accidental collisions, preserve unowned files, retain backups and failed rollback recovery. Test installed transitive imports.
8. Run standalone native checks for every role/state. They do not replace paint or interaction testing. Stop on permission denials; normal authorized escalation is distinct from bypassing restrictions.
9. Before live installs, switches, appearance changes or UI QA, coordinate with other owners and acquire the host QA lock if present. Check status first; acquire with your actual agent address, thread identifier and specific purpose. Keep the token, heartbeat at milestones and every five minutes, then restore and release. Never steal a stale lock or restart core/app to recover a slot. Release ownership if access is blocked.
10. During live QA, capture private screenshots locally, inspect status, test real controls and both appearances, and restore prior state. Stop on runtime exhaustion. Do not publish session content.
11. Document implementation, research, controls, limitations and distinct validation evidence. Use rich original previews, clearly labeled as illustrations. Publish only reviewed source/public artifacts, with signed commits and the appropriate repository topic when requested.

Use pnpm and mise tasks. Use daft for repository/worktree lifecycle; keep daft.yml tracked for the owner's repository. No package-install entry hook is needed while the project has no package dependencies.
